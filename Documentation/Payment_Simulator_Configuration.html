Payment Simulator Configuration Guide

📘 About This Guide
This document explains how to configure the Payment Simulator for the Virtual University Internship Management System. The payment system supports two modes: Simulator (for testing) and RabbitMaid (for production).

System Overview

The Internship Management System includes a payment module that handles:

  • Student Payments: One-time internship fees collected from students
  • Staff Payouts: Compensation for staff members and supervisors
  • Payment Accounts: Virtual wallets for each user
  • Transaction Tracking: Complete audit trail of all payments

Payment Drivers

Driver Purpose Use Case
simulator Testing and development Local development, automated tests, staging environments
rabbitmaid Production payments Live environment with real money transactions

Payment Simulator Setup

⚠️ Important: The Payment Simulator is a mock service for testing purposes only. It does not process real money transactions.

Step 1: Install Payment Simulator

1 Clone the Payment Simulator Repository 
git clone https://github.com/your-org/payment-simulator.git
cd payment-simulator
npm install
npm start
2 Verify the Simulator is Running

The simulator should start on http://localhost:3000 by default.

curl http://localhost:3000/health
# Expected response: {"status": "ok"}

Step 2: Configure Environment Variables

Add the following to your .env file:

# Payment Driver Selection
PAYMENT_DRIVER=simulator

# Payment Simulator Configuration
PAYMENT_SIMULATOR_BASE_URL=http://localhost:3000
PAYMENT_SIMULATOR_API_KEY=test_key_12345

# Payment Settings
PAYMENT_CURRENCY=XOF
PAYMENT_STUDENT_FEE_CENTS=50000
PAYMENT_STAFF_BASE_PAY_CENTS=25000
PAYMENT_SUPERVISOR_FIXED_BONUS_CENTS=10000
PAYMENT_PER_SUPERVISEE_BONUS_CENTS=5000
PAYMENT_SYSTEM_ACCOUNT_ID=
💡 Currency Note: The system uses XOF (West African CFA Franc) which has no decimal places. All amounts are stored as whole numbers (cents).

Step 3: Create System Payment Account

3 Login as Admin and Create System Account
  1. Navigate to Admin Dashboard → Payments → Settings
  2. Click "Create System Account" button
  3. The system will create a payment account for collecting/distributing funds
  4. Copy the generated Account ID
  5. Add it to your .env file as PAYMENT_SYSTEM_ACCOUNT_ID

RabbitMaid Integration

⚠️ Production Only: RabbitMaid should only be used in production environments with real payment credentials.

RabbitMaid Configuration

Add these variables to your production .env file:

# Payment Driver
PAYMENT_DRIVER=rabbitmaid

# RabbitMaid API Configuration
RABBITMAID_ENDPOINT=https://api.rabbitmaid.com
RABBITMAID_APPLICATION_KEY=your_application_key
RABBITMAID_ACCESS_KEY=your_access_key
RABBITMAID_SECRET_KEY=your_secret_key

# Service Configuration
RABBITMAID_STUDENT_SERVICE=mtn
RABBITMAID_STAFF_SERVICE=orange

# Payment Settings (same as simulator)
PAYMENT_CURRENCY=XOF
PAYMENT_STUDENT_FEE_CENTS=50000
PAYMENT_STAFF_BASE_PAY_CENTS=25000
PAYMENT_SUPERVISOR_FIXED_BONUS_CENTS=10000
PAYMENT_PER_SUPERVISEE_BONUS_CENTS=5000

Service Selection

RabbitMaid supports multiple mobile money services:

  • mtn - MTN Mobile Money
  • orange - Orange Money

You can configure different services for student payments vs staff payouts.

Configuration Variables Reference

Variable Description Example
PAYMENT_DRIVER Payment system to use simulator or rabbitmaid
PAYMENT_SIMULATOR_BASE_URL Simulator API endpoint http://localhost:3000
PAYMENT_SIMULATOR_API_KEY Simulator authentication key test_key_12345
PAYMENT_CURRENCY Currency code (ISO 4217) XOF
PAYMENT_STUDENT_FEE_CENTS One-time fee students pay (in cents) 50000 (500 XOF)
PAYMENT_STAFF_BASE_PAY_CENTS Base payment for all staff 25000 (250 XOF)
PAYMENT_SUPERVISOR_FIXED_BONUS_CENTS Fixed bonus for supervisors 10000 (100 XOF)
PAYMENT_PER_SUPERVISEE_BONUS_CENTS Bonus per supervised student 5000 (50 XOF)
PAYMENT_SYSTEM_ACCOUNT_ID System's payment account ID Generated by the system

Testing Payment Flows

Test Scenario 1: Student Payment

Prerequisites: Simulator running, system account created
  1. Login as a student user
  2. Navigate to My Payments
  3. Click "Create payment account"
  4. Click "Pay remaining" button
  5. Verify payment appears in transaction history
  6. Check that remaining balance is zero

Test Scenario 2: Staff Payout

Prerequisites: Staff user is an approved supervisor with assigned students
  1. Login as a staff user
  2. Navigate to My Payouts
  3. Click "Activate wallet"
  4. Verify computed payout amount is displayed
  5. Click "Request payout"
  6. Check payout history for the transaction

Troubleshooting

Error: "Account creation failed: Simulator did not return an account_id"

Cause: Payment simulator is not running or PAYMENT_SIMULATOR_BASE_URL is incorrect.

Solution:
  1. Verify the simulator is running: curl http://localhost:3000/health
  2. Check the PAYMENT_SIMULATOR_BASE_URL in your .env file
  3. Ensure there are no firewall rules blocking the connection

Error: "System payment account is not configured"

Cause: The system hasn't created its payment account yet.

Solution:
  1. Login as an admin user
  2. Go to Admin → Payments → Settings
  3. Click "Create System Account"
  4. Update PAYMENT_SYSTEM_ACCOUNT_ID in .env

Error: "Student has no payment account"

Cause: User hasn't created their payment account yet.

Solution: Users must click "Create payment account" or "Activate wallet" before making payments.
